# 2026-11-18 工作日志：html2apk 纯前端工具

## 需求演进
- 初版做了 Go 后端方案（server/ 目录，复用 apk-editor editor 包 + 自研 axml 修补器），用户随后明确要求**纯前端、无后端、无 JDK/JRE 依赖**，后端方案已删除。

## 最终方案（纯前端单文件）
- 交付物：`dist/html2apk.html`（3.70MB 单文件，双击即用，Chrome/Edge 103+）
- 架构：src/core.js（引擎，浏览器/Node 通用）+ src/ui.html（UI 模板）+ tools/build.py（构建：base64 注入模板 APK 与签名证书）
- 引擎三步（全部字节操作 + WebCrypto，算法移植自 ref/apk-editor 的 editor/signv2）：
  1. axml 修补：字符串池（UTF-16）解析重建，精确替换 label/versionName/包名/MainActivity 类名，versionCode 整型属性就地修补 —— 比参考项目的盲替换更强，支持中文与任意长度
  2. ZIP 追加式重打包：模板数据区原样保留（resources.arsc 保持 STORED+4 字节对齐，Android 11+ 必需），新条目 STORED 追加，重写中央目录+EOCD
  3. APK v2 签名：Merkle 分块摘要（0xa5 前缀 1MB 分块 → 0x5a+块数聚合）、RSA-PKCS1v15-SHA256（WebCrypto，PKCS#1 私钥手工转 PKCS#8）、签名块注入 CD 前并修补 EOCD

## 关键坑位
- APK v2 签名块布局：ID-value 对 = u64(pairLen=ID+value) + u32 ID + **u32(signers 总长)** + [u32(单 signer 长)+signer]，两级长度前缀缺一不可（对照 Go ParseV2Block 与官方规范确认）
- PKCS#1→PKCS#8 包装的 OCTET STRING 长度编码要区分短/长格式（0x84 标记）
- verify.py 的 DER 子元素遍历上界要用「TLV 起始+len」而非「contentStart+len」
- 测试策略：test/node-test.js（Node 22 无头跑三种模式）+ tools/verify.py（Python 独立按官方规范复算摘要 + RSA 公钥验签，端到端可信）
